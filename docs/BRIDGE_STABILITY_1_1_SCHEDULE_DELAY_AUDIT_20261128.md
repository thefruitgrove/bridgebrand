# BRIDGE Stability 1.1 — GitHub 예약 실행시각 위험관리

작성일: 2026-11-28 / 관측 기준: 대한민국 표준시(KST)

## 실증 확인
2026-11-28 오전 06:20 KST까지 main 브랜치에서 당일 `BRIDGE Daily Pipeline` 예약 실행 기록이 확인되지 않았다. 운영 Supabase `bridge_collection_runs`에서도 당일 00:00 KST 이후 수집 실행행이 조회되지 않았다. GitHub 공개 지수는 여전히 2026-11-27 기준 CPR/ENT/GOV/UNI 400건이었다. **이는 06:20 현재 정규 수집이 미실행 또는 예약 실행 지연 상태라는 관측이며, 당일 최종 발행 실패가 확정되었다는 뜻이 아니다.**

2026-11-27 정규 수집의 예약 시각은 05:15 KST, GitHub Action 실행 생성시각은 11:51:37 KST였다(396분 지연). 당일 정규 작업은 Google 뉴스 수집 단계에서 실패했고, 06:45 예약 복구 작업이 12:47 이후에 실행되어 최종 400건 자료 발행이 확인되었다. 다만 실제 GitHub 실행 기록상의 06:45 복구 Run은 12:47:58 KST에 생성되었으며, 정확한 수집·DB 발행 후속 시간은 별도 근거 없이 단정하지 않는다. 이 사례는 정상 공개 데이터와 정시 운영을 별도로 평가해야 할 필요성을 보여준다.

GitHub 공식 문서는 Actions `schedule` 이벤트가 서버 부하로 지연되거나 일부 누락될 수 있다고 명시한다:
https://docs.github.com/en/actions/how-tos/troubleshoot-workflows

## 추가 계측
`tools/bridge_schedule_slo.py`는 GitHub Actions가 실제 실행을 **생성한 시각(`created_at`)**과 예약 시각을 KST로 비교한다. 이는 Runner의 첫 단계 시작시각도, 실제 점수 발행시각도 아니므로 별도 지표로 저장한다. 신규 09:30 점검의 `scheduleAudit` 필드와 관리자 HTML에 기록한다.

| 업무 | 예약 | 60분 초과 또는 미생성 |
| --- | --- | --- |
| 정규 수집 | 05:15 KST | 지연/기한 초과 경고 |
| 근거 기반 복구 | 06:45 KST | 지연/기한 초과 경고 |
| 재수집 판단 | 07:15 KST | 지연/기한 초과 경고 |
| 홈페이지 검증 | 08:30 KST | 지연/기한 초과 경고 |

새 모니터는 예약 실행과 수동 실행을 구분한다. 수동 발행이 성공했더라도 GitHub 예약 실행의 정시성 점수로 계산하지 않는다. 이벤트 생성 전 시각에는 '예정 전', 시각 이후 60분 이내에는 '대기 중', 60분 초과 시 실행 기록이 없으면 '기한 초과'로 표시한다. 예약 실행의 실제 생성 이후 경과 지연이 60분보다 길면 '지연 실행'을 기록한다.

## 복구를 위한 구조적 판단
기존 수집·점수·DB·GitHub의 단일 실행 병행 제어는 그대로 유지한다. `cancel-in-progress:false`는 동일 대상에 대한 중복 점수갱신을 방지한다. 따라서 GitHub Cron을 시간당 추가하거나 중복 Dispatch를 무분별하게 실행하지 않는다. 시계 자체가 지연되는 문제는 재시도 횟수만 늘려 해결할 수 없다.

**정확한 오전 발행 시한을 보장해야 하는 경우**, GitHub Actions 예약 스케줄과 별도로 관리 가능한 외부 스케줄러(예: Cloudflare Cron Trigger, 외부 클라우드 스케줄 서비스)를 독립된 기준시계로 두고 GitHub Actions의 `workflow_dispatch`를 호출하는 방식이 필요하다. 단, 이 구조는 GitHub 토큰의 최소권한 보관·키 회전·중복 실행 차단·비용·실제 배포 계정 접근을 함께 검증한 뒤 적용한다. 현재 PR은 외부 스케줄러를 생성하거나 인증정보를 변경하지 않는다.

## 실제 성공 조건
(1) 개발 QA 성공, (2) 운영 main 병합, (3) 09:30 KST 예약 실행의 실제 실행 및 `scheduleAudit` 산출, (4) 대시보드 예약 지연 표시 대조, (5) 실제 발행 성공과 별개의 지연 추세 측정. 그 전에는 시각준수 자동검증을 실운영으로 완료했다고 말하지 않는다.
