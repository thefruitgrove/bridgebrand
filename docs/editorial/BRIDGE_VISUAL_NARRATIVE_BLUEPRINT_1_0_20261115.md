# BRIDGE Visual & Narrative Quality Blueprint 1.0
## 상세 해설·그림·도표·표·이미지·디자인 레이아웃·자동생성 PDF

2026-11-15. 실제 site/briefing.js, site/briefing.html, site/briefing.css, site/intelligence.html의 페이지·스타일·보고서 구성 기준을 확인해 작성한 설계 문서. **렌더링한 PDF의 최종 시각감사를 수행했다는 뜻은 아님.**

## 1. 최우선 기준: 설명을 줄이지 않는다
BRIDGE 보고서의 목표는 최대한 짧은 글이 아니라, **처음 보는 독자도 지표의 뜻, 숫자와 비교의 조건, 해석할 수 있는 범위, 다음 확인사항을 정확하게 이해하도록 설명하는 글**이다.

- **내용:** 개념 → 실제 평가 결과 → 수치와 자료 조건 → 비교 → 해석 → 예외와 한계 → 다음 질문의 흐름으로 충분히 해설한다. 필요한 내용은 길다는 이유로 삭제하지 않는다.
- **표현:** 전문용어가 필요한 경우 정의와 쉬운 설명을 충분히 붙인다. 형식적인 요약·기계적인 3문장·대칭 문단을 강요하지 않는다.
- **디자인:** 긴 설명을 작은 글씨로 욱여넣지 않고, 제목·소제목·단락·도표·그림·여백을 조정해 읽기 편하게 만든다.
- **일관성:** 기존 6단계 브리핑, 네이비·골드 기반 전문 매거진 톤, 명조 계열 헤드라인, 데이터 카드·그리드·표, 보고서 프린트 구조는 우선 보존한다.
- **보호:** 엔진·공식 점수·날짜·신뢰등급·6축 명칭·참조 축 제외·PDF 확정 쪽수 변경 없음. 필요 시 별도 승인.

## 2. 실제 코드에서 확인한 보고서 구조
- 국문 BASIC 18쪽; 국문 STANDARD 29쪽.
- 영문 BASIC 8쪽; 영문 STANDARD 29쪽. **영문 BASIC을 18쪽이라고 오기하지 말 것.**
- 출력은 printPage/printTable/printReading과 카드·그리드·강조 영역·보고서 푸터 조합으로 생성된다. 실제 각 페이지에 어떤 차트·그림이 렌더링되는지는 후속 브라우저/PDF 점검 대상이다.
- 웹 6단계: SIGNAL GUIDE → FIELD PULSE → POSITION READ → RELATIONSHIP INTELLIGENCE → PUBLICITY BRIEF → REPORT EDITION.
- briefing.css 내 easy-read-card:before의 한글 안내문에 잘못 디코딩된 것으로 보이는 텍스트가 확인됨. 실제 화면의 깨짐 여부는 미검증이므로 **시각 QA 후보**로 등록한다.

## 3. 한 페이지 안에서 설명과 시각자료가 연결되는 방법
|요소|본문의 역할|시각자료의 역할|검증|
|---|---|---|---|
|핵심 질문·제목|이 페이지에서 무엇을 설명하는지 알려줌|계층이 보이는 큰 제목|제목이 결과를 과장하지 않음|
|지표 풀이|측정대상·단위·자료 범위·기간을 충분히 설명|용어 카드·범례·개념도|처음 접한 독자가 이해할 수 있음|
|관측 결과|누구·언제·무슨 점수/순위인지 밝힘|표·막대·점분포·6축 도표|표·그래프와 실제 수치 일치|
|비교·해석|동일 조건에서 무슨 차이가 있고 어떤 의미가 있는지 상세 서술|차이를 보이는 그래프·비교 매트릭스|단순 차이를 원인으로 바꾸지 않음|
|관측 한계|참조/유지/실측의 상태, 누락, 비교 한계 설명|근거 상태 범례·주석|결측축을 실제 0/50점처럼 표시하지 않음|
|다음 질문|담당자와 독자가 추가로 확인할 내용 설명|확인순서·프로세스 도해|효과가 입증된 실행처방인 것처럼 과장 금지|

본문에서 그래프의 모든 셀을 반복할 필요는 없다. 그러나 중요한 변화·차이·예외·해석을 위해 필요한 수치는 생략하지 않는다. 필요한 문단은 여러 개로 나누어 **충분히 읽히게** 배치한다.

실제 생성기에서 확인된 제목과 역할에 맞춘 **개선안**. 일부 추천 시각자료는 이미 구현됐다고 단정하지 않는다.

|---|---|---|---|

## 5. 국문 BASIC 18쪽 — 기본형이라는 이유로 축약하지 않는다
- 1–4쪽: 표지·목차·분석 조건과 핵심 관측을 충분히 풀이.
- 5–8쪽: BRIDGE 정의·6축 공식 명칭·관측 상태·다른 지표와의 차이를 정확하게 소개.
- 9–13쪽: 분야 성과, T100 분포, 순위·간격, 일간·주간, 변화와 안정성을 설명.
- 14–16쪽: 중심 대상 6축·종합 해설·축 조합과 추가 질문.
- 17–18쪽: 활동량과 평판 수준을 구분하고 WHAT NEXT·PUBLICITY·다음 관측을 설명.
- BASIC은 단일 대상 중심으로 **충분한 설명을 제공하는 기본형**, STANDARD는 세 대상 비교·맥락·근거 해설이 확대된 전문형. 정보량 차이를 글의 난도로 만들지 않는다.

## 6. 웹 6단계 화면 디자인
1. SIGNAL GUIDE: 공식 정의 바로 다음 쉬운 풀이와 사례, 여섯 축 및 근거 상태 카드.
2. FIELD PULSE: TOP20의 산출기간과 ‘장기 성과’의 뜻을 설명. 추상적 ‘긴 호흡’만으로 지표 안내를 대신하지 않음.
3. POSITION READ: 같은 날·같은 분야의 상대 순위, 점수 차, 이전 순위 누락을 구별. 모바일에서 숫자와 툴팁이 읽혀야 함.
4. RELATIONSHIP INTELLIGENCE: 레이더·상태 표·선택 대상 설명·WHY 근거와 WHAT NEXT 질문을 연결. 차트만 따로 놓지 않음.
5. PUBLICITY BRIEF: 외부에 전달해도 사실과 해석 범위를 이해할 수 있는 완결된 설명문.
6. REPORT EDITION: BASIC/STANDARD의 분석 깊이와 대상 비교 차이를 명확히 설명하고 PDF 페이지·다운로드/인쇄 오류를 확인.

## 7. 그림·그래프·표·이미지별 필수 조건
- **표:** 제목·단위·기준일·출처·근거 상태·결측을 구분. 모바일에서 미세 글씨로 강제 축소하지 않고 가로 스크롤과 안내를 제공. PDF는 표 머리글/행이 부서지지 않도록.
- **점분포/막대/추세 그래프:** 동일 단위·정확한 스케일·축 제목·기간·범례. 기간/모집단 불일치 시 직접 비교하지 않음.
- **레이더:** 동일 축 순서와 범위; 참조축은 유효 점수와 뚜렷이 구별. 실제 점수가 없는 축을 관측된 50점으로 채운 듯 보이게 하지 않음.
- **개념도:** WHAT → WHY → WHAT NEXT와 데이터 계보는 좋은 도해 소재. 증명되지 않은 인과 관계에 화살표를 사용하지 않음.
- **사진/일러스트:** 실제 사진·기관 로고·기획 이미지·AI 생성 이미지의 성격을 구분; 출처·저작권·설명 대체텍스트 기록. 사건 자료가 없는 곳에 사실처럼 보이는 이미지를 만들어 넣지 않음.
- **그리드/카드:** 카드 수가 늘어도 제목과 본문이 여백에서 잘리지 않아야 하며, 색은 장식이 아니라 데이터 범주를 설명해야 함.

## 8. 문장·도표·레이아웃 통합 품질 게이트
- **G0 정확성:** 수치, 출처, 기준일, 관측 상태, 인과 과장 오류 0.
- **G1 설명 충분성:** 독자가 지표의 뜻·비교조건·해석의 이유를 본문만으로 이해 가능한지 점검. 도표만 나열하면 미통과.
- **G2 시각 정확성:** 그래프의 수치·축·단위·범례·누락값·사진의 종류와 출처 일치.
- **G3 레이아웃 품질:** PDF 텍스트 잘림, 고아줄, 표/캡션 분리, 폰트 대체, 화면 깨짐, 모바일 가독성 결함 없음.
- **G4 독자/전문가 검수:** 일반 독자 이해도와 경제·경영 전문가의 내용 정확성을 분리 평가.
- **G5 재현성:** 같은 스냅샷과 생성기에서 데이터·해석조건·편집 규칙이 동일하게 재현.

단지 문서·테스트 코드가 존재한다고 전체 품질 통과를 선언하지 않는다. 검증 상태는 **CODE CHECKED / RENDER CHECKED / HUMAN REVIEWED / RELEASE APPROVED**로 분리한다.

## 9. 검수 표본과 출력
- 분야별 CPR/GOV/UNI/ENT에서 대표 대상. 관측축만 있는 경우, 유지축 포함, 참조축 포함, 이전 비교 불가 사례를 균형 있게 포함.
- 국문 BASIC 18쪽, STANDARD 29쪽뿐 아니라 실제 코드가 갖는 **영문 BASIC 8쪽과 영문 STANDARD 29쪽**을 각각 점검.
- 긴 기업명, 외국어 혼합, N/R, 0P, 날짜 누락, 근거 없는 참조축, 여러 비교 대상 등 현실적인 출력 사례.
- PC/모바일 비운영 미리보기에서 실제 읽기 순서와 마우스/키보드/터치 상호작용 검수.
- 신뢰성 있는 결과를 얻으려면 기존/개정 보고서를 독자가 무작위 순서로 읽고 핵심 내용을 설명하는 방식으로 비교.

## 10. 이번 문서의 상태
실제 소스의 콘텐츠 구성·PDF 장수·웹 6단계·일부 CSS를 확인하여 설명·시각 편집 기준을 작성했다. PDF의 시각 결과, 사용자의 독해 결과, 모든 문장/이미지의 전수 검수는 **아직 완료되지 않았다.** 운영 통합 브랜치 및 공개 배포는 변경하지 않았다.
