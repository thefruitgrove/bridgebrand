# BRIDGE Stability 1.1 — 첫 정기 점검 사전검사 (2026-11-28)

## 실제 확인된 운영 상태
- 조사 시점: 2026-11-28 새벽 KST. GitHub main 공개 JSON의 `asOfDate`는 `2026-11-27`, `recordCount`는 400건. 정상적인 정규 수집 시작 전이므로 11월 28일 발행 실패로 분류하지 않는다.
- 11월 28일 09:30 KST 정기 종합 점검이 도래하기 전에는 운영 아티팩트 생성·7일 성공률·당일 발행을 성공으로 표시하지 않는다.
- Supabase `bridge_collection_runs`를 읽기 전용 조회한 2026-10-30~2026-11-28(KST) 집계에서 Google 뉴스 RSS 실행 68회/완료 성공 63회/실패 5회, OpenDART 공시 실행 63회/완료 성공 63회/실패 0회, 정부 공식평가 63회/63회/0회, 대학 공식자료 63회/63회/0회, YouTube API 63회/완료 성공 62회/실패 0회(1건 미완료·미확정). 이 수치는 **시도 건수**이지 30일의 발행 성공률이 아니다.

## 검증에서 발견된 운영 판정 위험과 조치
1. 부가적인 수집 성공률 조회 기능이 장애일 때 `SOURCE_METRICS_UNAVAILABLE`를 핵심 발행 실패로 기록하면, DB/Cloudflare의 400건 일치 검증이 통과했음에도 인위적인 '발행 실패' 경고가 발생한다. 본 수정은 자료원 통계 조회 오류를 별도의 경고로 분리한다. 모니터링 전체 실패 여부는 기존 400건 핵심 검증에 따라 판단한다.
2. 수집 실행행의 `status=success`이지만 `finished_at`이 NULL인 경우 성공한 작업으로 표시할 수 없다. 수집률 계산은 이미 완료시각이 있는 실행만 성공으로 계산했으나, '최근 실행' 표기에도 완료시각 검증을 추가한다.
3. 09:30 정기 워크플로우의 온라인 실행 전에 7일 성적표, 자료원 통계, GitHub 단계 진단, 대시보드 HTML, 400건 콘텐츠 무결성 테스트를 일괄 실행해 코드 오류를 먼저 차단한다.

## 운영 보존 원칙
- 자료 수집·계량 산식·원장·점수·DB 변경 없음.
- Cloudflare·GitHub 공개 JSON 내용 변경 없음.
- GitHub 저장소 공개 접근 가능성을 유지한 상태로, 관리자 HTML은 민감정보가 아닌 집계 결과만 표시한다.
- 신규 기능을 실서비스에서 확인하려면 **11월 28일 09:30 이후** 해당 날짜의 `BRIDGE 7-Day Reliability Monitor` Actions 실행 결과, JSON/HTML 아티팩트 업로드 및 GitHub Issue 동작을 실제 확인해야 한다. 자동 예약 실행이 지연되거나 누락되면 성공 기록을 만들지 않는다.
