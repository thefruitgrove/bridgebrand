# BRIDGE Stability 1.1 — 자료원별 수집 신뢰성 및 처리시간 계측

적용일: 2026-11-28 / 작업 범위: 운영관리 관측성 개선

## 목적
기존 운영 대시보드는 발행 성공과 실패 단계 확인에 초점을 두었다. 이번 모듈은 실패가 잦은 외부 자료원, 실패 이후 재시도로 복구된 사례, 실제 작업 평균 소요시간을 구별한다. 단순히 "최종 공개 400건 정상"이라도 수집에 반복적 실패가 있는 경우를 감출 수 없도록 한다.

## 실제 읽는 자료
`public.bridge_collection_runs`의 `source_id,status,started_at,finished_at`만 조회한다. 30일 내역을 KST 00:00 ~ 다음날 00:00(미포함)으로 한정하고, read-only REST `select`만 수행한다. SQL 결과의 `error_detail`, `diagnostics`, `window_start`, `window_end`, 출처 원문, 개인정보 및 API 키는 HTML과 공개 아티팩트로 출력하지 않는다.

## 판정 지표
- 실행 횟수 = 실제 기록된 해당 자료원 시도 수. **재시도도 별도 시도로 센다.**
- 성공 시도 수 = `status=success`이고 `finished_at`이 실제 존재하는 실행.
- 실패 시도 수 = `failed/failure/error`로 기록된 실행.
- 불완전 시도 수 = 성공 완료도, 실패 종료도 판정되지 않은 실행(예: `finished_at` 없는 성공 표시).
- 시도 성공률 = 성공 시도 수 / 전체 시도 수 × 100. **평가일 가동률이나 데이터 정확도가 아니다.**
- 관측일 수 = 해당 날짜에 하나 이상의 실행기록이 있는 고유한 KST 날짜 수.
- 성공일 수 = 완료된 성공 실행이 1회 이상 있는 고유한 KST 날짜 수. 같은 날 실패 후 성공했다면 성공일로 간주하되 실패 시도는 그대로 보존한다.
- 평균 작업시간 = 시작·완료 타임스탬프가 정상이고 0초 이상, 24시간 이하인 작업의 실행시간 평균. **완료된 모든 상태의 작업**을 포함한다.
- 30일 관측 기록이 0일 경우 성공률/평균시간은 **미측정**으로 출력한다.

## 표시할 자료원
Google 뉴스 RSS, OpenDART 공시, 기업 재무자료, 대학 공식자료, 정부 공식평가, 위키미디어 조회량, YouTube 공식채널, 뉴스 탐색(참고).

자료원 ID는 기존의 화이트리스트에 포함된 것만 집계하고 표시한다. 화면에는 자료원별 시도, 실패, 성공률, 평균 소요시간, 가장 최근 상태 및 관측일/성공일을 나타낸다. 실제 오류 상세는 별도 권한 있는 GitHub·Supabase 운영 로그에서 조사한다.

## 운영 경계
- 매일 09:30 KST 기존 `bridge-7day-reliability.yml`이 실행할 때 30일 집계값을 보고서 `sourceMetrics`에 함께 저장한다. dashboard HTML에도 포함한다.
- 민감정보·각 주체 원장·점수 산식·발행 프로세스·DB 스키마·Cloudflare 설정을 변경하지 않는다.
- 과거 수집 기록이 없으면 상태를 보정하거나 과거 실행을 생성하지 않는다.
- **30일 실행률**과 **30일 정상 발행률**은 다른 지표다. 30일 연속 발행 성적표는 30개의 실제 운영 검증 결과가 확보된 후에만 인정한다.
- 최초 2026-11-28 09:30 KST 자동 점검에서 JSON과 대시보드의 sourceMetrics를 확인하기 전에는 실서비스 연계 완료를 주장하지 않는다.
