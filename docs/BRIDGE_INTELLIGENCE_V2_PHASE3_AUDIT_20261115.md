## 이번에 수정한 실제 오류 위험
JavaScript `Number(null)===0` 특성으로 인해 없는 비교값을 `0` 또는 무변화로 표시할 위험이 있었다.

- `num()`, `signed()`: null/undefined/빈 문자열을 각각 N/R 및 비교불가 기호로 표기.
- `valid()`: `observed`·`maintained` 상태이면서 실제 수치가 있는 축만 유효 처리.
- `movementReading()`: 이전 순위/점수 변동값이 없으면 서술형으로 비교불가 안내.
- `render()`: 이전 순위 null은 '비교 대기' 표시. 비교값 누락 시 상승/하락 색 클래스 대신 중립 클래스.
- 기존 PDF 페이지 구성, 데이터 구조, 점수 엔진, 발행 프로토콜은 유지.

## 위험과 미완료 사항
1. 2026-11-14 데이터 계보 검증 실패, DB와 공개 JSON 버전 차이, 회귀검사 실패는 Work의 별도 감사 결과에 따른 미해결 과제다. 본 변경으로 해결됐다고 볼 수 없다.
2. WHY의 원자료별 *기여도*는 현 브리핑의 `printEvidence()`에 포함되지 않는다. 스냅샷에 정의된 기여도 스키마와 감사 계보를 먼저 확인해야 구현할 수 있다. 임의 근거나 인과적 설명을 생성하지 않는다.
3. WHAT NEXT는 이미 존재한다. 신규 추천 엔진 구축보다 기존 규칙형 결과의 근거 연결·우선순위 정당화가 우선이다.
4. 이 변경은 GitHub 저장소 파일 및 정적 단언 검토까지 수행했다. 실제 `node --check`, Python 테스트, 브라우저/PDF 출력, CI 통합검증, 운영 배포는 별도 실행·확인이 필요하다.
5. `main` 또는 실서비스에 병합하지 않았다.
