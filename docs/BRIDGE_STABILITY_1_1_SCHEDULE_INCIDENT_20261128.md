# BRIDGE Stability 1.1 — 예약 실행 지연 전용 GitHub Incident
작성일: 2026-11-28

## 문제의 구분
정규 발행 자체가 실패한 것과 예약 실행 시각이 지연된 것은 별개의 위험이다. 예컨대 05:15에 실행되어야 할 작업이 11:51에 시작하고 12시 이후에 최종 발행됐다면, 해당 날짜 데이터 400건이 결국 일치해도 정시 운영을 성공으로 보고할 수 없다.

## 처리 절차
1. 09:30 KST 종합점검에서 `scheduleAudit`을 읽어, 정규 수집·근거 복구·재수집 판단·실서비스 검증 4개 예약 이벤트의 최초 생성시각을 수집한다.
2. 예약 시각에서 60분을 초과하고 실행 이력이 없거나 실제 시작이 60분 이상 지연된 경우, 기존 발행 실패 Incident와 별도로 `BRIDGE SCHEDULE: scheduled pipeline late or not started` 이슈를 연다. 같은 제목의 열린 Issue가 있으면 코멘트로 누적해 중복 생성을 방지한다.
3. 나중에 4개 예약작업 모두 당일 측정 기록이 있고 기준 내일 때만 해당 이슈를 종료한다. 데이터를 얻지 못한 경우를 정상으로 추정해 자동 종료하지 않는다.
4. 이슈에는 사전 허용된 업무 명칭, 지연 상태, 지연 분 단위 수치와 GitHub Actions 실행 링크만 적는다. 공급자 오류 상세·비밀값·개별 데이터는 출력하지 않는다.

## 한계
이 Issue는 09:30 종합점검이 실제로 실행된 후에 생성된다. GitHub의 Cron 자체가 지연되면 Issue도 늦게 생성될 수 있다. 그러므로 **독립 시계 기반의 즉각적인 예약 장애 감지/해결 기능은 아직 아니다**. 향후 별도 인증된 외부 스케줄러의 독립 Watchdog을 마련해야 오전 정시 발행의 운영 SLA를 보장할 수 있다. GitHub의 `schedule` 이벤트는 정확한 시각을 보장하지 않으며 실행 자체가 일부 누락될 수 있다.

## 안전성
기존 수집·점수·DB 발행·Cloudflare 설정은 변경하지 않는다. 현재 제어권이 없는 외부 서비스·GitHub 토큰·Cloudflare Worker를 임의로 생성하지 않는다.
