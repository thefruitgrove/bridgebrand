# BRIDGE 주간 갱신 레시피 (UPDATE RECIPES)

> 이 파일은 "각 평판 축이 어떤 자료원에서·어떤 공식으로·어떤 주기로 산출되는가"를
> 영구 기록한다. 매주(week 전환 시) 이 레시피를 그대로 재현하면 데이터가 갱신된다.
> **신규 자료원/축이 추가되면 이 파일에 한 줄씩 append 한다.** (삭제하지 않는다)
>
> 표기 규칙: [축] 자료원 → 변환함수(engine2/axis_extension.py) → 갱신주기 | 비고

## ─────────────────────────────────────────────
## 1. 변동성 데이터 (주간 갱신 대상 — THIS WEEK의 핵심)
## ─────────────────────────────────────────────

- [R 반응] 뉴스·공표명단 사건 탐색 → r_axis(심각도×귀속계수×시간감쇠) → **매주** | 부정사건 없으면 R=100(verified). ※ THIS WEEK에 뜨는 대상은 주로 이 축이 그 주에 움직인 경우다.
  ※ 심각도: 경미5 / 중대15 / 심각30 / 초대형50
  ※ 귀속계수: A(직접)1.0 / B(관련)0.5 / C(간접)0.2 / D(무관)0.0 / F(전직)0.3
  ※ 시간감쇠: (1/2)^(경과일/반감기), 기본 반감기 90일 · 초대형 180일
  ※ 피해자는 귀속 D=0.0 (예: 손흥민 취재진 뒷담화 — 본인 피해라 감점 없음)

- [G 행동유발·CPR] 분기/연간 매출 증감률 → g_axis = clamp(50 + 증감%/20×50) → **분기** | 각사 IR·경영실적 발표
  ※ 이상치 컷: ±50% 초과 제외. 예) 현대차 +6.3%→G65.8, 삼성SDI −20%→G0

## ─────────────────────────────────────────────
## 2. 비변동성 데이터 (연 1회~반기 갱신 — 공식 통계 기반)
## ─────────────────────────────────────────────

- [E 책임·CPR] 한국ESG기준원(KCGS) ESG 통합등급 → esg_to_e_axis(S~D) → **연 1회(10~11월)** | 등급표 업로드로 일괄 반영
  ※ 매핑: A+83.3 / A66.7 / B+50.0 / B33.3 / C16.7 / D0.0
  ※ ESG D등급은 '무사건 고득점'을 교정하는 핵심 (예: 리노공업 86.7→43.4)

- [E 책임·GOV] 기재부 공공기관 경영평가 종합등급 → public_eval_to_axis(S~E) → **연 1회(6월)** | 보도자료 참고2 등급표
  ※ 매핑: S100 / A80 / B60 / C40 / D20 / E0

- [G 행동유발·UNI] 대학알리미 정원내 신입생 경쟁률 증감(전년대비) → g_axis(증감형) → **연 1회** | 대학알리미 CSV
  ※ 이상치 컷: ±50% 초과 제외

- [D 경험·UNI] 대학알리미 전임교원 1인당 재학생 수 → 표본 내 백분위(역방향) → **연 1회** | 대학알리미 CSV
  ※ 이상치 컷: 1인당 5명 미만 제외(의대 아티팩트 방지, 을지대 1건 제외)

- [B 도달·CPR] KRX 시가총액 순위 → rank_to_b_axis(순위, 100) → **반기** | 목록이 시총순이라 순위 그대로 변환
  ※ 공식: 100×(1 − ln(순위+0.5)/ln(전체+1.5))

- [B 도달·ENT] 인스타그램 공식/개인 팔로워 → 로그정규화 100×log(팔로워)/log(기준) → **반기** | 나무위키 팔로워 순위표
  ※ 기준 reference ≈ 198,734,470 (방탄 7,500만=94.9 앵커로 역산)
  ※ 그룹은 공식계정, 배우/솔로는 개인계정 팔로워 사용

- [I 정체성] 잡플래닛 평점(5점) → jobplanet_to_i_axis((x−1)/4×100) → **분기** | 수식어 HHI 병행
- [B 보조] 사람인 관심기업 수 → saramin_to_b_axis_aux → **분기** | B축 보조지표

## 3. 주간 갱신 실무 순서 (week 전환 시)
## ─────────────────────────────────────────────

1. data/bridge_data_v2.json 의 "week" 문자열을 새 주차로 변경
2. published 는 실제 데이터 수집일로 설정(배포일 아님 — 정직성 원칙)
3. 위 §1(변동성) 중 그 주에 실제 변한 대상만 재탐색:
   - R축: 신규 부정사건/공표명단 확인 → 있으면 감점, 없으면 R=100 유지
   - G축: 분기 실적 발표 시점이면 매출 증감 갱신
4. §2(비변동성)는 해당 갱신월에만 (대부분 연1회) — 등급표/CSV 받아 일괄
5. build.py && build_spa.py 재빌드 → site/ 배포
6. THIS WEEK는 evidence 날짜 최신순으로 자동 정렬되므로, 새 근거가 들어오면 자동 상단 노출
